# MATLAB execution and method

Set `MATLAB_EXECUTABLE` to your actual installation, e.g. the detected `E:/mat/bin/matlab.exe`, and `MATLAB_METHOD=batch`. The adapter runs a fixed `run_route_analysis` invocation with a server-generated manifest path. It uses argument arrays, not shell execution. Browser strings cannot become MATLAB code or filesystem paths.

Alternatively install the MATLAB Engine API matching your release/Python version and set `MATLAB_METHOD=engine`. A separate Python child process starts Engine, adds the trusted script directory and invokes the same function. MATLAB Production Server is not implemented. Runtime alone is unsupported.

Run the wizard/checker to verify startup and both Image Processing Toolbox and Mapping Toolbox licenses. The adapter uses a writable preferences directory under `MATLAB_WORK_DIR`, captures a local log, enforces execution timeouts and terminates cancelled processes. Logs are not served as public artifacts.

## Method: experimental-sar-ndvi-v1

1. Check input existence, band order, distinct acquisition records, projected map-cell references, identical grids/CRSs/dimensions, no-data convention and valid pixels. Reject incompatibility. Upstream export must align images; automatic image registration is intentionally not substituted.
2. Preserve dB inputs or convert explicitly labeled positive linear power once. Apply a 3×3 median speckle filter. Erode validity one pixel so invalid neighbors cannot create valid support.
3. Use the maximum absolute VV/VH difference. Require a configurable 3 dB default threshold and difference at least local mean + 0.5 local standard deviation over a 9×9 neighborhood. This is an uncalibrated heuristic.
4. For optical imagery, use upstream SCL masks and correct B4/B8 mapping. Compute before/after NDVI and loss. Where both optical observations are valid, require default NDVI loss >0.2 as support for the SAR candidate. Else retain SAR-only candidates.
5. Gate slopes between the configurable 10° default minimum and 45° maximum. Remove components smaller than nine pixels. Steep-slope exclusion is a conservative limitation, not a complete SAR layover/shadow model.
6. Calculate coarse raster road overlap. Python polygonizes the actual MATLAB mask and computes vector candidate area, centerline/corridor distance, corridor intersection and potentially affected centerline length. A separate 20 m assumed road width determines potential direct impact.
7. Write JSON statistics, projected GeoTIFF change and validity masks, SAR change PNG, NDVI change TIFF/PNG where available. Input comparison previews are generated from actual exported rasters. Python publishes GeoJSON only after output validation.

The broad analysis corridor and the assumed road footprint have different meanings. Corridor intersection identifies slope context. Neither intersection establishes physical obstruction. No trained CNN or probability model is included because the supplied files contain no training dataset or validation evidence.

Manifest interface: `files`, `scenes`, `sar_units`, `sar_bands`, `optical_bands`, `epsg`, `nodata`, thresholds, `output_dir`, `segment_id`, algorithm and warnings. Paths are generated by the trusted worker. MATLAB returns `results.json` containing `valid_fraction`, changed pixels, components, mean absolute dB change, optical support pixels, raster road overlap, timestamps and method identifier. See the actual source for exact fields.
